# Website enquiry submissions

The homepage project brief POSTs to `/api/inquiries` using the permitted production origin. Required fields are name, phone, chosen service and enquiry text. Optional budget/features are preserved. The form never redirects on a failed/unparseable response. Its same-payload retry key prevents a lost response creating duplicate records. The server commits the enquiry, owner mail queue entry and audit record atomically before returning a success receipt.

The owner sees saved records under **Website enquiries / 官网咨询**, backed by the existing persistent database. `/api/admin/inquiries` and `/api/admin/tools` require the owner session. Public confirmation accepts a signed, expiring receipt and exposes only a non-contact reference; it never returns name, phone or message. Basic per-IP/global rate limits and a honeypot reduce unsolicited submissions. WhatsApp stays a separate, voluntary contact link.

`https://kennystudio.cfd/thank-you` serves a noindex confirmation page. The page checks `/api/inquiries/confirmation` before showing success. Direct/invalid visits do not emit a success event. A verified visit emits `kenny_inquiry_success` to `window.dataLayer` with `transaction_id` set to the enquiry reference. A tab-local marker prevents refreshes emitting it again. Conversion events contain no customer name, phone or message. No Google conversion account ID, label or tag is invented or installed by this change. Configure Google Ads/GTM to consume the verified event, use its transaction ID for deduplication, and apply the site's measurement consent settings. Counting every direct page view as a lead bypasses this verification.

Deploy the backend first, verify startup, then publish the new homepage bundle, form CSS, privacy copy and thank-you assets. Old WhatsApp-only homepage code continues to work until the static site updates. Existing orders, payments, accounts, branding, scroll motion and social links are preserved. Public enquiry records are not invoices or paid orders.
